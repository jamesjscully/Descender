# Explicit Algebraic Lee Expanders: Right Abstraction

Date: 2026-05-15

## Reframe

The object we need is not "a good tilt matrix" in isolation.  It is a
systematic linear code in the Lee metric.

For a group of `g` free coordinates and `r` pivot rows, choose

```text
P : F_q^g -> F_q^r
G(y) = (P y, y) in F_q^(r+g)
```

The certificate target is:

```text
for every y != 0:
  Lee(P y) + Lee(y) >= L
```

Equivalently, the graph code generated by `[P; I_g]` has minimum Lee distance
at least `L`.  Once we have such a block code, the existing Lean boundary
`SystematicLeeDistanceAtLeast` immediately feeds
`ModqNoLeeKernelVectorBelow`.

This is the right abstraction because it separates three problems:

1. **Code construction:** choose an explicit algebraic graph code.
2. **Distance proof:** prove its Lee minimum distance.
3. **Descender integration:** place the block diagonally inside the solved map
   `B0^{-1} B1`.

## What The Literature Suggests

The most relevant classical object is a Lee-metric BCH/Reed-Solomon-style code.
Roth and Siegel prove Lee-distance lower bounds for BCH codes over `GF(p)`;
their summary states that a class of BCH codes with a run of consecutive roots
has minimum Lee distance at least `2r`, and gives additional Reed-Solomon-case
bounds for larger root runs.  That is the closest known algebraic-code template
to our problem.

Recent work on Lee-metric bounds emphasizes that Lee distance needs its own
generalized support notions and does not behave like Hamming distance.  This is
important for Descender: Hamming expansion alone is not enough unless it is
converted into a centered-amplitude bound.

Compressed-sensing expander/RIP-1 work is also relevant, but it should be viewed
as an integer `l1` expansion route rather than a Lee-code route.  Sparse
expander matrices can preserve `l1` norm for sparse vectors; if we can prevent
modular wrap below the target, an integer `l1` expansion theorem would imply a
Lee expansion theorem.  This is promising for sparse explicit matrices, but it
does not automatically solve the dense arithmetic Lee problem.

## Candidate Algebraic Families

### 1. Systematic Lee-BCH or Lee-RS Codes

Construct a known Lee-metric BCH/RS code `C` of length `N = r + g` and
dimension `g`, then convert a generator matrix to systematic form `[P; I_g]`.
The Lee distance of `C` becomes the exact graph-code Lee certificate.

Pros:

- Most canonical algebraic route.
- Existing Lee-distance theory is directly applicable.
- Systematic conversion is a standard linear-algebra step if the chosen free
  coordinates are an information set.

Cons:

- The basic designed bound `d_Lee >= 2 * root_run` is probably too weak for our
  compact parameter targets.  For `L = 3277`, a linear `2r` guarantee would
  require about `1639` redundant rows, while random-code budgets suggest tens
  to hundreds of rows.
- The refined Reed-Solomon bounds may help, but this needs a parameter
  evaluator before we know whether the family is viable.

Basic-bound sanity check:

```text
profile  L     BCH-style rows from d >= 2r
128      3277  1639
192      1173  587
256      2979  1490
```

These row counts are far outside the useful region, so plain Lee-BCH designed
distance is not competitive.  Only a much stronger refined RS/Lee bound or a
different theorem could make this family viable.

Verdict:

Use as the first explicit-code benchmark.  If the refined RS/Lee bounds are
still far from the random-code row budgets, do not spend Lean effort here
except for documenting the negative result.

### 2. Vandermonde/Moment Graph Codes

Let rows be evaluations against a moment curve:

```text
(P y)_t = sum_j scale_j alpha_t^(e0 + j) y_j
```

This is the systematic graph-code version of polynomial evaluation.  The proof
target becomes:

```text
low-Lee coefficients y cannot have many low-Lee evaluations f(alpha_t)
```

Pros:

- Natural bridge from Descender's existing Cauchy/Vandermonde-style algebra.
- Generation is compact and deterministic.
- There may be a proof using resultants, Newton identities, product formulas,
  or sublevel-set bounds for low-degree polynomials over `F_q`.

Cons:

- Hamming MDS guarantees only many nonzero evaluations, not large Lee values.
- The real theorem is an arithmetic anti-concentration statement for polynomial
  values, which is substantially harder than root counting.

Verdict:

This is the best explicit-algebraic research target if Lee-BCH bounds are too
weak.  The right next experiment is a Vandermonde block evaluator comparing
exact/small-group Lee distance against the random-code bound.

Initial probe results:

- The naive `e0 = 0` family is dead.  The degree-zero column is constant across
  rows, so a one-coordinate vector can make every pivot row a small repeated
  centered value.  For the 128-bit `q = 32771, g = 8, r = 26, L = 3277` probe,
  unscaled/midpoint/geometric variants produced below-target relations with
  Lee weight `28`.
- Shifting to `e0 = 1` removes the constant-column defect, but deterministic
  midpoint/geometric column scales still create small arithmetic progressions.
  At `g = 8, r = 26`, shifted midpoint/geometric variants produced a
  below-target relation of Lee weight `353`.
- The relevant comparison must use the random-code row budget, not the much
  smaller exploratory `r = 26` row count.  At the 128-bit random-code-style
  budgets, shifted moments with deterministic random nonzero column scales
  survived the current bounded attacks:

```text
q      L     g   r    best found Lee weight   status
32771  3277  8   104  12463 / 13757          no counterexample found
32771  3277  16  66   5965 / 9261            no counterexample found
32771  3277  32  46   3705 / 4741            no counterexample found
32771  3277  32  42   3349                  no counterexample found
32771  3277  32  41   3265                  counterexample found
```

These are not proofs.  They are enough to say that the first serious theorem
target should be a shifted, randomly scaled moment graph-code certificate,
starting with the `g = 32, r = 42` or `g = 32, r = 46` shape.  The `r = 42`
case is the smallest seed-1 row count that survived the current attack, while
`r = 46` gives a more comfortable margin and matches the earlier random-code
budget.

The proof obligation should be stated directly as:

```text
For fixed public nonzero scales c_j and evaluation points alpha_t,
every nonzero y in F_q^g satisfies
  Lee((sum_j c_j alpha_t^(1+j) y_j)_t) + Lee(y) >= L.
```

The most likely proof route is an arithmetic anti-concentration theorem for
low-degree polynomials with scaled coefficients, not an MDS/Hamming-distance
argument.

### 3. Integer `l1` Expanders / RIP-1 Blocks

Choose `P` with small integer entries and prove an integer inequality:

```text
||P z||_1 + ||z||_1 >= L
```

for all nonzero integer `z` in the relevant low-`l1` range.  If every below
target vector has no modular wrap, the integer theorem implies the Lee theorem.

Pros:

- Connects to explicit expander and sparse-recovery literature.
- Sparse matrices give good key-generation cost.
- Proof shape can be graph-combinatorial rather than field-arithmetic.

Cons:

- Standard expander RIP-1 theorems are support/sparsity based and may be too
  weak for dense low-amplitude vectors.
- Modular wrap must be controlled explicitly.

Verdict:

Good secondary explicit path, especially for sparse setup cost.  It should be
framed as "integer robust nullspace / RIP-1 implies Lee" rather than as a
q-ary coding theorem.

### 4. Character/Cyclotomic Pseudorandom Blocks

Use deterministic row sets from multiplicative subgroups, characters, or
cyclotomic classes so that row dot products behave like the random-code model.

Pros:

- Could approach random-code row budgets without setup randomness.
- Proof might use character sums or Weil-type bounds.

Cons:

- Hardest proof path.
- We do not yet have a concrete theorem statement matching the Lee lower tail.

Verdict:

Keep as a later path if Vandermonde/moment blocks show strong empirical
behavior.

## Recommended Explicit Path

Use the following sequence:

1. **Benchmark Lee-BCH/RS.**
   Add a small evaluator for the published Lee-BCH/RS lower bounds.  Decide
   whether any known bound can reach our `L` with row counts near the
   random-code target.

2. **Test Vandermonde/moment graph codes.**
   Generate deterministic `P_{t,j}=alpha_t^j` blocks for group sizes
   `g = 4, 8, 16`.  Use exact verification where feasible and heuristic
   counterexample search where exact verification is not feasible.  Compare
   against the random-code row budget.

3. **Look for the theorem behind successful Vandermonde instances.**
   If they behave randomly, formulate the proof as a polynomial
   anti-concentration theorem:

   ```text
   A nonzero low-Lee coefficient polynomial cannot have low-Lee values at too
   many chosen evaluation points.
   ```

4. **Keep RIP-1 as the sparse fallback.**
   If Vandermonde fails or proof looks intractable, pursue sparse integer
   expanders with a no-wrap bridge to Lee.

## Lean-Level Interface

The explicit-family theorem should target the existing abstraction:

```lean
SystematicLeeDistanceAtLeast q P L
```

For block constructions, add a deterministic direct-sum theorem:

```lean
BlockLeeDistanceAtLeast q P_block L ->
DirectSumBlocksLeeDistanceAtLeast q blocks L
```

Then convert to:

```lean
ModqNoLeeKernelVectorBelow q (systematicDualMap q P) L
```

This keeps the Descender proof stack independent of which explicit family wins.

## Decision

The right level is **systematic Lee-code construction**.

Do not start by editing the Cauchy theorem again, and do not search arbitrary
dense matrices.  Start by asking:

```text
Which explicit linear Lee code of dimension g and length g+r gives the best
provable minimum Lee distance?
```

The first concrete implementation step should be a Lee-BCH/RS bound evaluator
and a Vandermonde/moment block evaluator.  These will tell us whether existing
algebraic Lee-code theory is numerically competitive or whether we need a new
polynomial anti-concentration theorem.
