# HIGH-1 SUF-CMA Response/Opening Malleability — Canonical-Domain Fix

Status: fixed (verifier range-check + signer canonicalization). No byte-layout,
response-bound, or SIS-box change. Not committed.

## 1. The bug (reproduced)

The local-delta relation verifier recovers, per repetition, a `mask_view` from the
signed responses:

```
mask_view[coord] = response[coord] - sign * pk_free[block][coord]   (mod Q)
```

and accepts iff

```
local_state(mask_view) = mask_view[0] + 50 * mask_view[1] (mod Q) == fiber_state
AND openings == mask_view + pad.
```

`local_state` is a linear map `F_q^2 -> F_q`. Over the in-box square
`mask_view[i] in [-RESPONSE_BOUND, RESPONSE_BOUND] = [-48, 48]` its kernel is
generated by the integer vector `(50, -1)`:

```
local_state(v0 + 50, v1 - 1) = (v0 + 50) + 50*(v1 - 1) = v0 + 50*v1 = local_state(v0, v1).
```

The Fiat-Shamir challenge frame (`challenge_hash_frame`,
`prodref::...challenge frame`) binds `(pk, msg, slot, digest, proof_commitment)`
but NOT the response/opening bytes. So given one honest signature an attacker
shifts the recovered `mask_view` by `±(50, -1)` (when the shifted rep is still
in-box), recomputes the (deterministic, seed-derived) pad openings, and obtains a
SECOND byte-distinct signature for the SAME message with NO secret key — a
SUF-CMA / non-malleability break.

Concrete witness from the repro test: for `fiber_state = local_state(12, -12) =
11701`, the two in-box reps are `(12, -12)` and `(-38, -11)` (difference exactly
`(50, -1)`, since `12 - (-38) = 50` and `-12 - (-11) = -1`).

## 2. Kernel + canonical-window choice (exhaustive proof)

Exhaustive enumeration over `q = 12289`, `RESPONSE_BOUND = 48`, `slope = 50`
(`/tmp` reproduction; numbers below):

- reachable fiber states (cosets with at least one in-box rep): **4897**
- **maximum in-box reps per coset: 2**
- cosets with exactly 2 in-box reps: 4512
- the set of difference vectors between the two reps of any 2-rep coset is
  **exactly `{(50, -1)}`** — confirming the kernel direction and that no coset
  has reps spaced by a larger multiple.

Canonical fundamental domain (local, verifier-checkable from a single rep — the
verifier never sees the sibling): a centered in-box rep `(c0, c1)` is **canonical
iff one further step in the `+(50, -1)` direction leaves the box**:

```
canonical(c0, c1)  <=>  c0, c1 in [-48, 48]  AND  NOT ( (c0+50) in [-48,48] AND (c1-1) in [-48,48] )
```

This selects, within each coset, the rep with the larger first coordinate.

Uniqueness (proven exhaustively): **cosets without exactly one canonical in-box
rep: 0** (all 4897). Because each coset has at most two reps differing by `(50,
-1)`, exactly one of them can take a further `+(50, -1)` step inside the box, so
exactly one is canonical. Single-rep cosets are trivially canonical (no sibling
in box).

For the repro witness: `canonical(12, -12) = true`, `canonical(-38, -11) =
false`. The honest signer's rep is the canonical one; the forgery's shifted rep
is rejected.

## 3. The fix

Verifier range-check + signer canonicalization. Helper
`mask_view_is_canonical(mask_view)` (centers each coord into `(-Q/2, Q/2]`,
requires in-box, then applies the rule above) added in both crates.

Verifier (reject non-canonical), three sites — all reachable accepting paths:

- scaffold standalone `verify_local_delta_relation_with_masked_witness`
  (q12289 bin) — used by the quotient/public-quotient proof verifiers;
- scaffold inlined relation inside
  `verify_stateful_signature_with_hidden_preimage_relation` (q12289 bin);
- deployable masked path `verify_public_local_fiber_consistency`
  (`production_reference.rs`) — the reviewed-Fq12 account-carried checked-core
  verifier and the public local-consistency statement both route through it,
  and it shared the identical recover-mask_view / check-`local_state` structure.

New reject reason on all three: `"non-canonical local mask view in round {rep}"`.

Signer canonicalization: the honest signers already emit the canonical rep.
`reference_sign_with_proof` (hence `production_sign` and the KAT corpus) and
keygen all hardcode `mask_view = [12, Q-12] = (12, -12)`, which is canonical.
The only signer that did not was the helper `mask_view_for_fiber_state` (used by
the non-proof `reference_sign` path): it scanned `lhs` ascending and returned the
smaller-`v0` rep `(-38, -11)`, the NON-canonical sibling. It is now constrained
to return the canonical rep (`&& mask_view_is_canonical(mask_view)`), so that
path's emitted openings are accepted by the stricter verifier.

## 4. Hiding preservation argument

The canonical rep does not leak more about the witness than before:

- The fiber map `local_state` and the recovered `mask_view` are **public
  functions of the already-published responses and public key** — the verifier
  recomputes `mask_view` from bytes the signature already contains. The
  canonical check is a deterministic predicate on that public quantity; it adds
  no new function of any secret.
- Honest behavior is **unchanged**: the honest signer already emitted the
  canonical rep `(12, -12)` (the entire codebase — keygen, proof signer,
  production signer, KAT — uses exactly this rep). The signer's output
  distribution is byte-identical before and after (verified: KAT reproduces
  byte-for-byte, see §5). The fix removes accepting non-canonical reps from the
  verifier's accept set; it does not change what the signer reveals.
- The only signer touched, `mask_view_for_fiber_state`, now emits the canonical
  rep instead of the kernel sibling. Both reps are deterministic functions of
  the same public `fiber_state`; choosing the canonical one of two
  publicly-derivable reps reveals nothing additional about the witness — the
  fiber state itself is unchanged, and the rep is a public coset representative.
- Net: the change is a verifier-side tightening to a canonical coset
  representative, which is the standard non-malleability hardening. No
  witness-hiding regression.

## 5. Impact: byte sizes UNCHANGED, SIS box UNTOUCHED

- `RESPONSE_BOUND` = 48 (unchanged); SIS response box / margin unchanged
  (`response_difference_coeff_bound` = 96, shortest-intersection-vector bounds
  unchanged in the emitted report; the 96 < 114 margin is untouched).
- Public key size: **172 bytes** (before and after — no `PK_BYTES` /
  `PK_SEED_BYTES` / `PK_PAYLOAD_BYTES` change).
- Signature sizes: **260 bytes** (q12289 stateless), 187 / 228 / 254 (target)
  bytes — all derived from unchanged layout constants
  (`CHALLENGE_BYTES`, `ACTIVE_RESPONSE_BYTES = 52`,
  `LOCAL_OPENING_BYTES_PER_REP = 4`, …). No struct or encoding changed.
- KAT corpus byte-for-byte reproducible: `--kat-check` reports "reproduces
  byte-for-byte"; tests `kat_v0_corpus_reproduces_frozen_json` and
  `kat_v0_corpus_is_internally_consistent` pass. **No regen needed** — honest
  signer reps were already canonical, so accepted openings for honest signatures
  are unchanged.

None of the hard impact guardrails ((a) pk/sig byte size, (b) RESPONSE_BOUND /
SIS box, (c) hiding regression, (d) structural redesign) were hit. The fix is
the expected clean verifier range-check + signer canonicalization.
