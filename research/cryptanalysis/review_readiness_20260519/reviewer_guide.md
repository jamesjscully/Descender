# Reviewer Guide

Date: 2026-05-19

This guide is meant to focus third-party review on the assumptions most likely
to invalidate a deployment claim.

## Highest-Risk Questions

1. Does the keygen story really exclude the relevant
   `PublicViewNarrowDualWitness`, or is that still an unquantified hardness
   assumption?
2. Does the concrete signer instantiate `RejectionSamplingCertificate`, and is
   retry timing hidden or modeled?
3. Does the production verifier implement exactly the same byte relation as
   the Lean verifier and the Rust prototype?
4. Does the query-log Fiat-Shamir game cover the production EUF-CMA game,
   including multiple oracle queries and signing queries?
5. Does frozen-target cryptanalysis support the claimed concrete security
   level beyond the formal `2^-133` blind-challenge term?

## Files To Start With

- `target_spec.md`: frozen byte format and profile.
- `target_theorem.md`: intended deployable ROM claim.
- `theorem_map.md`: Lean endpoints and review questions.
- `assumption_ledger.md`: concise assumption inventory.
- `assumption_review.md`: detailed risk analysis and closure criteria.
- `q12289_conformance_vectors.json`: generated byte-level conformance vectors.
- `cryptanalysis_plan.md`: attack work that must be archived before review.

## Recommended Review Order

1. Check that `target_spec.md` and `q12289_conformance_vectors.json` describe
   the same byte language as the Rust verifier.
2. Check the Lean challenge codec and q14/hash-frame endpoints in
   `theorem_map.md`.
3. Audit the A4 keygen/no-bad-public-view assumption before spending time on
   implementation performance.
4. Audit the A6 signer distribution and retry behavior.
5. Review the cryptanalysis artifacts against the exact frozen q12289 target.

## Stop Conditions

Review should stop and the target should be revised if any of the following
are found:

- a byte-format mismatch between Lean, Rust, and the spec;
- a feasible bad-public-view witness for the frozen keygen target;
- secret-dependent signer leakage not covered by the sampler theorem;
- a transcript malleability or parser ambiguity that changes the hash frame;
- a practical attack below the intended concrete security level.
